# v1.78 公開規格的下一輪重構與逐章修訂計畫（候選）

> 2026-10-22 · 根據本輪[公開覆蓋複核](./公開覆蓋複核與差異清單_20261022.md)提出。**以下是修訂提案，不是使用者已逐條批准的全新正式規則**。P-02 持續有效：只做文件治理與設計，不開始智能體／城市程式開發。R-01～149 保留，私人母版不改寫、不公開。

## 1. 將歷史堆疊變成可溯源的「四層文檔」

| Layer | 建議位置 | 權威及目的 | 禁止 |
|---|---|---|---|
| L0 決議與已批准需求 | `current/` + `requirements/` | 149 項現行語義、DEC 日期／覆寫、主人正式批准範圍 | 讓歷史時點的臆測覆蓋 v1.78 |
| L1 工程資料契約 | `current/`、`world/`、`research/` | 對每個子系統分別定義輸入、輸出、版本、權威、單位、有效域、失敗回執 | 將候選欄位假稱已實作 |
| L2 驗收與證據 | `tests/`、`research/` | 紙面 fixture、預註冊量測條件、反證、實測入口與缺資料標記 | 以表格列數換算 PASS |
| L3 歷史及私人來源映射 | `history/` + **私人母版** | 舊版效力、撤回決議、來源行號／私下保存的原始資料索引 | 直接上傳私人逐字檔及未授權圖片 |

每一份公開文件頂端應有：`source_version`、`authority_state`、`superseded_by`、`source_scope`、`evidence_level`、`runtime_status`、`privacy_review`、`owner_decision_needed`、`last_reviewed_at`（可逐項標 `UNKNOWN`）。

## 3. 建議先改的三組文字

**修訂 A：要求數量描述。** 不再寫「除了隱私都完整公開」，改寫為：「149 項正式要求皆有匿名技術對照；歷史補充已依來源復原若干獨立表格；未逐字公開私人母版，部分歷史測試、權利資料與科學原件尚未全數核對。」這是可檢查而不誇張的表述。

**修訂 B：24-DPB。** 避免直接寫「DPB-15 ＝體溫」而不附版本；改為「`DPB52_PROPOSED:15` 是體溫，另一歷史名稱空間的 15 曾為 HPA，兩者仍待映射。跨版不得直接按裸數字 join」。正式決議前不可選定單一最終表。

**修訂 C：自主生活驗收。** 對所有「她在一天中做了 X」補 `PAPER_FIXTURE` 或實際 `WORLD_RECEIPT`，並把 `CHOSE_IDLE`、`NOT_ATTENDED`、`RESOURCE_STARVED`、`OFFLINE_GAP` 列為不同原因。相同人格、未讀訊息與沒有成果都可以是合法結果。

## 4. 每一輪修訂應產出的四項可檢查證據

1. **差異清單**：舊來源代碼與位置、現行有效文字、修改原因、未決事項，含可能被覆寫的下游引用。
2. **安全公開材料**：每一新增表格的來源版本與列數；不得直接把私人 Word/MD 或未核准原圖貼到 PR。
3. **反例驗收表**：格式統一為 `fixture → possible observations → action/intention → expected receipt → forbidden receipt → source`，另列所有 `NOT_RUN`。
4. **版本與公開閘門**：只有使用者核對後才可能從 Draft PR 合併 main；核准開發智能體是獨立於合併文件的 P-02 決策。

## 5. 停止條件與未解決工作

若 source 文本無法逐條查明、模擬值沒有模型適用域、版權或合法刪除存在未決衝突，就使用 `SOURCE_UNVERIFIED`、`UNKNOWN`、`CANNOT_REDISTRIBUTE` 或 `OPEN_HARD_BLOCKER`，不填漂亮數字、不造通過率。

優先研究下一個真實缺口：**24-DPB 原兩份互相衝突的命名表完整來源和 N57-T／DAY75 的逐條原始 fixture**；若缺資料，先把現有明確決議與 source pointer 定稿，暫不推定剩餘細節。OCT/PAD 仍暫緩，P-02 仍有效。
