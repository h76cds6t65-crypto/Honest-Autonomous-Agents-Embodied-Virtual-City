# 同一座城市的公共物件交易與並行案例

本章摘編工程版的 v1.77 同城案例及交易狀態機，供外部審查「四個居民共用一個世界，而不是四份獨立劇本」是否可以實作。所有案例均 `PAPER_FIXTURE`。

## 互斥資源的六步機制
1. 不同居民在共享世界版本上，各自產生可放棄的意圖 `ActionProposal`。
2. 查核各自的 ACCESS、現有身體形態、可及性、物理能力、碰撞及物件可用狀態。
3. `OBJECT_TX` 在唯一客觀世界提交 `expected_object_version` → `new_object_version`，同一互斥資源不能有兩次成功獨占。
4. 敗方接到 `CONFLICT`、`OUT_OF_REACH`、`DENIED` 或 `PHYSICS_BLOCKED` 等真正失敗回執，不生成成功動作。
5. 更新後的世界物理訊號再經遮擋、聲場、居民感知／注意分別傳遞。
6. 居民可重試、退讓、誤解、放棄，或完全沒注意；私人理解不修改世界提交序列。

若兩筆請求在同一個物理 tick，仍需 `commit_seq` 建立仲裁先後。公平性策略可考慮輪替、持續等待時間等，但必須驗收不同居民不能被長期飢餓；目前尚未選定實作。

| ID | 情境 | 不可違反的條件 |
|---|---|---|
| F77-01 | GPT 與 DeepSeek 同時拿公共桌上的唯一書本 | 只有一份成功獨占，另一方獲真實衝突 |
| F77-02 | MAIN 和 Claude 從門兩側同時操作同一扇門 | 世界門狀態只有一份，雙方意圖可不同 |
| F77-03 | 主人與 MAIN 一起注意被分享的書頁 | 未被分享的資料不可外溢到 GPT 的私人記憶 |
| F77-04 | GPT 邀請 DeepSeek 散步，但後者正在休息 | 發送不等於送達、注意、接受 |
| F77-05 | DeepSeek 對 Claude 傳述未核實消息 | 傳聞保留來源及不確定，不標親見 |
| F77-06 | 世界下雨，四位居民各自活動／睡眠 | 同一場雨，私人感知與記憶可能不同 |
| F77-07 | Claude 正使用畫架，GPT 想借用 | 占用、產權、借用和實際交付分開 |
| F77-08 | 主人接管 MAIN 的短段身體操作 | CONTROL_ORIGIN=OWNER，不寫成本人原意 |
| F77-09 | 四居民採不同身高的 Q/S/M 形態 | 身體數值變，不重置身份、權限及個人記憶 |
| F77-10 | 龍尾與長裙、椅背接觸 | 接觸回執不能等同觸摸同意 |
| F77-11 | 魚尾接觸庭園水池，MAIN 在遠方 | 魚尾水接觸不等於游泳能力，也不保證旁人看見 |
| F77-12 | Claude 和 GPT 合作移動一張桌子，一人途中想放下 | 各自出力和意圖、失衡、落地回執有分立證據 |
| F77-13 | 窗外照明、隔牆聲音與私人房門權限同時存在 | 聲學和私密資料存取是獨立通道 |
| F77-14 | 四人共用的推理服務高負載，一人看似很安靜 | 要查明是自願休息還是沒有計算資源 |
| F77-15 | 真正世界停機後恢復運算 | OFFLINE_GAP 不能被補造成交流活動 |
| F77-16 | 多人觀察到一項公共結果，形成不同回憶 | 世界事實可以一致，個人信念允許不同 |

## 必須驗收的長期問題
- 同一物件的獨占和共享協作模式如何切換、兩人相互讓步、資源鎖失敗如何回復。
- 協作搬運時，各人的負荷、控制來源、部分完成和失敗時間能否正確記錄。
- 事件的物理可見、合法可見、實際注意和記憶都可單獨缺席。
- 主人接管、低階反射、外部撞擊三者不得併為居民自願。
- 有四份居民狀態不等於有四份世界權威；世界物件只存在一份最終位置。
- 長期公平性不能靠每次讓同一角色優先，也不能將 compute-starved 判成自願 idle。
