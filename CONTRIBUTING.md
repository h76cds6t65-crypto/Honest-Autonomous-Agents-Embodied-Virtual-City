## 中文｜歡迎提供可以核對的研究意見

我們歡迎物理、機器人、AI 架構、模擬系統、隱私治理、資料工程、語言翻譯及人文研究方面的具體意見。**不必先同意所有設計主張，反例尤其有價值。**

提交 GitHub Issue 時，請盡可能提供：

1. **對應位置：** 文件路徑、版本、編號（例如 `DPB-19`、`R-153`、`Q07`、`#28`、`NEW-08`、`D14`、`G77`）及實際行號／段落。
2. **問題分類：** 技術錯誤、缺少來源、歷史效力衝突、中英文語義不一致、驗收設計漏洞、合法資料與隱私問題，或新的工程候選。
3. **可檢查的理由：** 明確敘述錯誤、反例、數學推導、適用域、參考文獻、預期行為；無證據處標示 `UNKNOWN`。
4. **候選修正：** 建議的新表述、假設、受影響的相鄰系統以及可能造成的副作用。允許只報問題而未提出解法。
5. **狀態不要誤寫：** `APPROVED` 是人類已批准的設計，`PROPOSED` 是候選，`NOT_RUN` 代表測試尚未實際執行，`PAPER_CLOSED` 不是軟體驗證通過。

**貢獻不等於自動批准。** 公開 Issues、翻譯、意見或 PR 不會自動成為新的 R 條文或推翻原已批准規則；專案發起者保留現行設計的審核與決議權。P-02 保持有效：不因此授權建立或部署居民程式。

**隱私與權利：** 請勿貼上個人姓名、私人對話、角色日記、登入憑證、API 密鑰、私有檔案、未獲授權的圖片或其他人的機密資料。安全問題請先避免公開具有可利用細節的敏感資料；不要猜測存在未公開的私人資料。第三方素材需核實使用權；本倉庫目前沒有明示全面商用及重製許可。

## English｜How to submit a verifiable review

We welcome grounded criticism from robotics, physics, AI, scientific modeling, virtual environments, privacy engineering, data governance, translation and humanities. **Counterexamples and disagreements are welcome**; contributors need not agree with the project's worldview.

For a helpful issue or document review:

1. **Cite the exact source:** filename, historical version, item identifier (`DPB-19`, `R-153`, `Q07`, `#28`, `NEW-08`, `D14`, `G77`) and source line/heading.
2. **Classify the concern:** technical contradiction, missing evidence, outdated historical authority, Chinese–English translation drift, weak acceptance criteria, privacy/legal concern or a new engineering candidate.
3. **Explain what is falsifiable:** scenario, counterexample, equations and units, evidence source, expected versus actual results, and uncertainty where data are absent.
4. **Propose a narrow revision if possible:** what changes, what remains approved, adjacent requirements affected, and unwanted downstream effects. A well-grounded problem report **does not** require a complete solution.
5. **Keep status claims factual:** `APPROVED` does not mean implemented; `PAPER_CLOSED` is not a software pass; `NOT_RUN` means there is no executed result.

Public discussion, translations and proposed pull requests **do not automatically supersede owner-approved design decisions** or grant development authorization. P-02 is active: agent coding and deployment require separate explicit approval after planning.

**Protect people and rights:** Do not post private chats, identifiers, resident diaries, credentials, API keys, unpublished original source or unauthorized third-party media in public issues. Avoid publishing exploitable private security details. Public read access does not itself supply a commercial or redistribution license.
